## Objective

Deliver the complete M2 milestone from `docs/19_planning/19_01_milestones.md`: pair two devices and transfer one regular file over a single TLS 1.3 control/data path with durable ACK and atomic completion. This milestone resolves `TBD-SEC-KEY-001` (device key algorithm/strength) and the M2-required subset of `TBD-LIMITS-001` (parser, handshake, and frame ceilings).

## Prerequisites

- **M1 complete:** M1-001 merged (PR #4, `dbd333b`). Offline content engine, durable store, CDC, manifests, reconstruction, and GC are available.

- **TBD-LIMITS-001 (M2 subset) resolution required:** Select and document default and absolute ceilings for frame header/payload bytes, manifest bytes over the wire, file/chunk counts per session, path bytes, concurrent handshakes, connection timeouts, and handshake timeouts. ## Scope

1. **Identity initialization and permission checks** (ARCH-01): Generate device key pair using the algorithm selected by TBD-SEC-KEY-001, create self-signed device certificate, store private key with restrictive permissions, load identity into TLS context, and validate key strength on startup. Reject weak/deprecated keys.
2. **Pairing ALPN and TLS exporter SAS** (ADR-003, API-001): Implement the `spoink-pair/1` ALPN restricted pairing state machine. Derive SAS from TLS exporter material and both identities/nonces. Both users confirm; default is reject. One listener accepts one attempt. Store confirmed peer SPKI pin in trusted_peers (DB-001). Test MITM/mismatch simulation.
3. **Pinning and revocation**: Normal `spoink/1` connections require mTLS against pinned SPKI fingerprints. Implement pin verification, revocation (local, immediate for new connections), same-key certificate renewal acceptance, and re-pairing requirement for new-key renewal.
4. **Wire protocol framing** (ADR-007, API-001–011): Implement the 32-byte fixed frame prefix parser, CBOR header decoder, and payload handling with the limits from TBD-LIMITS-001. Validate magic/version/channel/type/reserved/lengths before allocation. Handle partial TCP reads. One chunk per frame (API-007). Parser fuzz corpus.
5. **Protocol state machine**: Implement HELLO exchange, capability/version negotiation, SESSION_OFFER/ACCEPT/REJECT, MANIFEST_BEGIN/PART/END paged transfer, TRANSFER_PLAN (single file), CHUNK_PUT/ACK/NACK, FILE_RESULT, SESSION_RESULT, CANCEL, ERROR, and PING/PONG. Enforce message ordering and one-session binding. Single data connection.
6. **Interactive receive/send with raw codec**: Implement sender CLI that selects one file, manifests it using M1 engine, connects to a paired receiver, offers a session, sends manifest and chunks. Implement receiver CLI that listens, accepts session, receives manifest, builds transfer plan (request all chunks for the one file), receives chunks durably into the M1 store, reconstructs and finalizes.
7. **Durable chunk ACK and whole-file verification**: Receiver durably stores each chunk via M1 store before sending CHUNK_ACK. Sender tracks ACKs. On all chunks received, receiver reconstructs, verifies whole-file SHA-256, and sends FILE_RESULT success/failure. Sender receives SESSION_RESULT. No partial final file at destination.
8. **Limits resolution**: Document and enforce the M2-required subset of TBD-LIMITS-001: frame ceilings (confirm rabin-v1 max_bytes 65536 fits), manifest size over wire, handshake timeouts, connection timeouts, concurrent handshakes, and per-session file/chunk counts for single-file scope.
