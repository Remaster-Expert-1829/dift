# Risk Register

> Status: Approved baseline  
> Scale: Probability and impact are Low / Medium / High relative to this project.

| ID | Risk | Probability | Impact | Mitigation | Detection | Contingency |
|---|---|---:|---:|---|---|---|
| RISK-001 | CDC implementation/profile is unstable or provides weak reuse for target changes. | Medium | High | Parameterized deterministic implementation, golden/property tests, EXP-CDC-001 corpus before profile freeze. | Distribution/reuse benchmarks; cross-build golden mismatch. | Ship a revised versioned profile before v1 freeze; retain correctness even if savings are lower. |
| RISK-002 | Pairing/TLS bootstrap admits MITM or mismatched identity. | Medium | High | Restricted pairing ALPN, TLS-exporter SAS, both-side confirmation, pinned SPKI, no 0-RTT. | Security test proxy, auth audit events, key-change rejection. | Block release; simplify to manual full-fingerprint pin if SAS design cannot be verified. |
| RISK-003 | Filesystem+SQLite crash window loses acknowledged chunks or creates unsafe state. | Medium | High | Ordered durable commit, ACK last, startup reconciliation, fault injection at each step. | Crash matrix; store doctor; receipt/blob invariant check. | Stop ACK/receive, enter recovery mode, request invalidated chunks again. |
| RISK-004 | Path or symlink race writes outside destination root/overwrites unintended data. | Medium | High | Strict normalization, descriptor-relative/no-follow operations, explicit overwrite, destination reservation. | Adversarial path/race tests and code review. | Disable directory recursion/overwrite until safe resolver passes; block release. |
| RISK-005 | Multiple TCP connections reduce performance/fairness or overload receiver. | Medium | Medium | Hard bounds, one-connection static mode, fair queue, probe-one-at-a-time scheduler, resource telemetry. | Static/adaptive paired benchmarks, starvation/resource tests. | Default to one/static connection; keep parallel mode experimental. |
| RISK-006 | Adaptive controller oscillates or mistakes receiver/storage delay for network degradation. | High | Medium | Explicit application signals, cooldown/hysteresis profiles, receiver-pressure signal, replay/simulation tests. | Decision traces, oscillation/no-starvation tests. | Fall back to static bounded policy; do not claim adaptive improvement. |
| RISK-007 | Compression routing spends more CPU/time than it saves. | High | Medium | Operator modes, entropy precheck, discard larger result, separate validation corpus. | CPU/wall/byte benchmark matrix. | Default auto to conservative/raw or LZ4; keep codecs opt-in. |
| RISK-008 | Chunk store grows without safe reclamation or GC deletes live data. | Medium | High | Normalized references, recomputable counts, leases, grace, dry-run, conservative uncertainty behavior. | Property tests, store inspection, periodic reconciliation. | Disable automatic GC; retain data and require reviewed manual maintenance. |
| RISK-009 | Source changes during manifest/transfer create stale or mixed file content. | Medium | High | Source identity/metadata checks plus hash verification on bytes actually sent; fail `SOURCE_CHANGED`. | Mutation integration tests; hash mismatch telemetry. | Require source retry/new session; optional future snapshot integration. |
| RISK-010 | Custom protocol parser has memory/CPU vulnerabilities. | Medium | High | Limit-first fixed framing, deterministic CBOR schema, checked arithmetic, fuzzing/sanitizers. | Fuzz corpus, resource tests, security review. | Reduce accepted surface/limits; block network release until fixed. |
| RISK-011 | SQLite write serialization limits concurrent transfers. | Medium | Medium | Short transactions, WAL, file I/O outside transactions, batched safe reads/telemetry. | Busy/transaction metrics and concurrent stress. | Lower concurrency; optimize schema/transactions; external DB is not an automatic response. |
| RISK-012 | Benchmark claims are unfair or irreproducible. | High | High | Predeclared methodology, relevant baselines including rsync/static mode, raw results, confidence reporting. | Independent reproduction/review; environment/raw artifact audit. | Remove or qualify claim; never substitute roadmap estimates. |
| RISK-013 | Solo-project scope prevents a correct release. | High | Medium | Vertical milestones; M3 is useful core; advanced scheduler/compression polish is deferrable. | Milestone exit reviews, defect/risk trend. | Release a smaller honest core; do not weaken security/integrity gates. |
| RISK-014 | Plaintext local chunk store surprises users or leaks on disk theft. | Medium | High | Explicit documentation/UI notice, trusted-device scope, restrictive permissions, recommend disk encryption. | Security review and user docs check. | Add at-rest encryption only through new ADR/store migration; do not imply TLS covers disk. |
| RISK-015 | Identity loss/corruption breaks pairings. | Medium | Medium | Safe creation, permission checks, optional protected backup instructions, doctor. | Startup identity validation. | Generate new identity and re-pair; received files remain. |
| RISK-016 | Library/version/licensing vulnerability blocks distribution. | Medium | Medium | Pinned dependencies, SBOM/notices, vulnerability/license scans, wrapper isolation. | CI scan and release review. | Upgrade/replace dependency; disable optional codec capability if necessary. |

## Review cadence

Review at every milestone exit and before public claims/releases. A realized risk links to defects/tests/ADRs. Closed risks retain resolution evidence; probability alone never closes a risk.
